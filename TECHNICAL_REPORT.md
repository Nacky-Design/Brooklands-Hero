## Ограничения и сравнение

Слева сохранены H1 и CTA, справа/снизу автомобиль 3/4, справа компактные статичные пресеты; мобильная версия вертикальная. Используются серое помещение, низкий подиум, мягкая тень, локальная процедурная текстура бетона, без внешних изображений/HDRI/CDN.

Архитектура и освещение существенно проще утверждённого PNG: без сложного проёма и растительных теней. Карточки показывают названия и условные образцы, без вырезанных из референса фотографий. Фотографическая точность не достигнута. В исходном GLB запечённые блики и дефекты формы/текстуры; независимые материалы без дополнительной разметки невозможны. Metalness 0 и roughness 0.9 сохранены. Типографика временная системная.

Нет backend, формы, дополнительных страниц, смены материалов, нового автомобиля или постобработки геометрии. Пресеты не интерактивны; меню/CTA явно сообщают о демо. DPR ограничен 1.5, тяжёлых постэффектов нет. Safari/iOS, Android на реальном устройстве, потеря WebGL-контекста на реальном GPU и стабильный FPS на целевом оборудовании — NOT VERIFIED.

## Исправление долгого запуска GLB

Пользователь подтвердил, что опубликованная модель загружается, но ожидание заняло около двух минут. Ошибка отсутствия файла не подтверждена. Внешние GitHub Pages-запросы из текущей среды по-прежнему блокируются proxy (CONNECT 403), поэтому время именно публичной загрузки здесь измерить нельзя.

Исправлены обнаруженные дефекты запуска:

- До исправления запрос GLB начинался только после запуска JS приложения. Теперь HTML запускает preload GLB параллельно со скриптом. Проверено: единственный запрос модели, инициатор `link`; GLTFLoader использует загруженный ответ.
- Проверка WebGL ранее вычислялась при каждом React-render и оставляла лишний GPU-контекст. Теперь это lazy initializer, только WebGL 2 (требование используемой Three.js); пробный контекст освобождается. Проверено: многократное открытие/закрытие демо-сообщения не вызывает новых WebGL-проб.
- Вместо непрерывного рендера используется `frameloop="demand"`: загрузка, поворот и resize запрашивают кадры; damping продолжает кадры до остановки. Проверено: в покое счётчик кадров не растёт, кнопки и drag возобновляют рендер. Это снижает расход GPU в покое, но не означает подтверждения высокого FPS во время вращения.
- Обработчик потери WebGL-контекста снимается при размонтировании.

Контрольное локальное измерение production под `/Brooklands-Hero/`, Chromium SwiftShader, viewport 1440 × 900: до исправления начало GLB ~1284 ms / готовность ~3261 ms; после — начало GLB ~23 ms / готовность ~2392 ms. Это отдельные локальные запуски, не статистический бенчмарк и не замер задержки пользовательской сети/GitHub CDN. Двухминутное ожидание локально не воспроизведено.

Повтор: `node scripts/qa-loading.mjs` при статическом production-сервере на 4180 с префиксом `/Brooklands-Hero/`; для dev: `QA_LOADING_DEV=1 QA_LOADING_URL=http://127.0.0.1:5173/ node scripts/qa-loading.mjs`. Результаты — `artifacts/qa-loading-production.json` и `artifacts/qa-loading-dev.json`.

Повторная проверка после исправлений: 320, 430, 1440, 1536 px — PASS в первом запуске. На 1920 px первый запуск завершился преждевременной проверкой клавиатурного поворота через фиксированные 650 ms в software WebGL. Тест исправлен на ожидание фактического угла (с timeout 15 s), проверки не отключались. Повтор 1920 и 2048 px — PASS; тач, прокрутка, WebGL fallback и reduced motion — PASS. `qa-results.json` объединяет прошедшие результаты двух запусков с полем `sourceRun`; исходный неуспешный запуск сохранён в `qa-demand-first-run.json`, повтор — в `qa-demand-rerun.json`. Дизайн и GLB не менялись.
