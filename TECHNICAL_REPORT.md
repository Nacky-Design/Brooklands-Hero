## Исправление долгого запуска GLB

Пользователь подтвердил, что опубликованная модель загружается, но ожидание заняло около двух минут. Ошибка отсутствия файла не подтверждена. Внешние GitHub Pages-запросы из текущей среды по-прежнему блокируются proxy (CONNECT 403), поэтому время именно публичной загрузки здесь измерить нельзя.

Исправлены обнаруженные дефекты запуска:

- До исправления запрос GLB начинался только после запуска JS приложения. Теперь HTML запускает preload GLB параллельно со скриптом. Проверено: единственный запрос модели, инициатор `link`; GLTFLoader использует загруженный ответ.
- Проверка WebGL ранее вычислялась при каждом React-render и оставляла лишний GPU-контекст. Теперь это lazy initializer, только WebGL 2 (требование используемой Three.js); пробный контекст освобождается. Проверено: многократное открытие/закрытие демо-сообщения не вызывает новых WebGL-проб.
- Вместо непрерывного рендера используется `frameloop="demand"`: загрузка, поворот и resize запрашивают кадры; damping продолжает кадры до остановки. Проверено: в покое счётчик кадров не растёт, кнопки и drag возобновляют рендер. Это снижает расход GPU в покое, но не означает подтверждения высокого FPS во время вращения.
- Обработчик потери WebGL-контекста снимается при размонтировании.

Контрольное локальное измерение production под `/Brooklands-Hero/`, Chromium SwiftShader, viewport 1440 × 900: до исправления начало GLB ~1284 ms / готовность ~3261 ms; после — начало GLB ~23 ms / готовность ~2392 ms. Это отдельные локальные запуски, не статистический бенчмарк и не замер задержки пользовательской сети/GitHub CDN. Двухминутное ожидание локально не воспроизведено.

Прежняя `Architecture.jsx` удалена. В прозрачном Canvas только реальная GLB, студийный свет и контактная тень; фон — локальный HTML image layer. Существующие H1/меню/карточки/CTA остаются отдельной HTML-вёрсткой. На мобильных дополнительно опущен ракурс и сдвинута модель к линии пола. GLB не редактировалась, SHA-256 совпадает с исходной.
